# Phase 10 — WordPress.org README and Packaging

## Objective
Prepare a clean WordPress.org submission package.

## readme.txt
Include:
- Plugin name.
- Contributors.
- Tags.
- Requires at least.
- Tested up to.
- Requires PHP.
- Stable tag.
- License.
- License URI.
- Description.
- Features.
- Installation.
- FAQ.
- Screenshots.
- Changelog.

## Maximum tags
Use no more than five relevant tags.

Suggested:
- woocommerce
- product management
- product catalog
- product editor
- product quality

Verify current WordPress.org rules before submission.

## Description
Use factual language.

Suggested:

> Catavio helps WooCommerce store owners find common product information issues from one simple dashboard. Scan products, review missing or incomplete information, and jump directly to the standard product editor to make corrections.

Avoid:
- Best.
- #1.
- Ultimate.
- Guaranteed.
- 10x.
- Fake statistics.
- Unverified performance claims.

## Packaging
Package only required production files.

Verify:
- Correct plugin header.
- License file.
- readme.txt.
- uninstall.php.
- Human-readable source.
- Correct asset paths.
- No development secrets.
- No `.env`.
- No API keys.
- No local machine paths.

## License
Use GPL-compatible licensing.

## Screenshots
Prepare screenshots showing:
1. Dashboard.
2. Product health list.
3. Product detail.
4. Scan results/progress.

Do not include:
- fake data presented as real.
- pricing.
- promotional claims.
- fake reviews.

## Exit criteria
The zip is structurally valid and ready for WordPress.org submission review.
